# Neural-network surrogate: training code and deployed weights

Part of the data repository for *A hybrid global–2D model for SF₆/Ar inductively coupled plasma etchers with neural-network acceleration*.

Everything needed to inspect, re-run or re-train the surrogate reported in section 5
of the manuscript.

## Layout

```
two_species/
  scripts/    train_ensemble.py      the production trainer (SeparateHeadsMLP)
              arch_sweep.py          joint head vs per-species heads
              ablation_study.py      the training-recipe sweep of table 4 / figure 20
              ml_dataset_loader.py   dataset assembly from the solver output
              run_*_parallel.py      the launchers used on the cluster
  ensembles/  ml_production_ensemble_legacy/   5 seeds, the deployed model
              ml_production_ensemble_lxcat/    5 seeds, the LXCat-mode counterpart
all_species/
  scripts/    train_species.py       per-channel trainer
              single_head_arch.py    SingleHeadMLP, one network per channel
              species_loader.py      per-channel dataset assembly
  ensembles/  ml_production_ensemble_all_species/<channel>/  21 channels x 5 seeds
```

## Provenance of the deployed weights

`data/surrogate/split_manifest.json` names the ensemble behind every two-species
number in the paper:

    "ensemble": "results/ml_production_ensemble_legacy"
    "sanity_rmse_ensemble_mean": { "nF": 0.005405969, "nSF6": 0.007569795 }

Those are the 0.00541 and 0.00757 reported in section 5.3 and table 5. The directory
here is that ensemble, with its `config.json` and `summary.json` alongside the weights.

The 21-channel band of 1.6e-3 to 8.9e-3 in section 5.4 comes from the 105 checkpoints
under `all_species/ensembles/`, summarized in
`data/surrogate/ml21_channel_metrics.json`.

## Two things to know before re-training

**The random Fourier encoding is hardwired.** Both `SeparateHeadsMLP` and
`SingleHeadMLP` register the frequency matrix `B` as a buffer with no switch to disable
it, so `B` is the first key of every saved `state_dict`. The deployed weights are
therefore Fourier weights. Section 5.2 and supplementary section 5 report that a
raw-input network is more accurate on this target, and that is the configuration we
recommend for reuse; adding a `use_fourier=False` branch is a small change to the two
model classes.

**The training dataset is not included here.** It is roughly 350 MB of per-condition
solver output and is regenerated by running the physics model over the 220-point
operating grid (`model/`), then assembled by `ml_dataset_loader.py`. The split is
recorded in `data/surrogate/split_manifest.json`, so the exact train/validation
partition can be reconstructed without the raw files.

## What the run records say, and how to check them

Each set of weights ships with the `summary.json` and `config.json` its training run wrote.
Those are the primary provenance: `rate_source` names the corpus the run trained on, and
`metrics.rmse` is the ensemble-mean validation RMSE on log10 density that the paper reports.

Both deployed ensembles record `rate_source: legacy`, the Maxwellian-averaged (Lallement) rate
set described in section 5.2. Their metrics reconcile with the paper exactly: the two-species
pair against `data/surrogate/split_manifest.json`, and all 21 channels against
`data/surrogate/ml21_channel_metrics.json`. `verify_package.py` checks both.

`two_species/ensembles/ml_production_ensemble_lxcat/` is a variant trained on the Boltzmann-rate
corpus. It is kept for comparison and is **not** reported in the paper, which describes the 110
deployed checkpoints: five seeds for the two-species model and five for each of 21 channels.
